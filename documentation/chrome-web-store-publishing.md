# Automatic Chrome Web Store publishing

The GitHub release workflow calls `publish-chrome-web-store.yml` after creating the release. It submits the same ZIP to the existing store item `ejamgmkhipipigkanaefjklolfddmlel`.

The job checks the published SHA-256 digest, the digest from the release build, the ZIP manifest version, and that the tag belongs to the official main history. It does not rebuild the extension. Google reviews the revision and makes it available automatically after approval, using the listing's existing visibility and rollout settings.

Publishing stays disabled until the one-time Google configuration is complete and the repository variable `CWS_PUBLISH_ENABLED` is `true`. GitHub releases continue to work while it is disabled.

## One-time Google setup

Use a Google Cloud project you administer and the Google account that owns the existing Chrome Web Store listing. The API cannot create a new store item. Its listing and privacy information must already be complete in the Developer Dashboard.

The integration uses a service account through GitHub Workload Identity Federation. No JSON private key, OAuth client secret, or refresh token is stored in GitHub. The account needs no project-wide Owner or Editor role.

The following commands use `gcloud` in an authenticated terminal. Substitute your project ID. If resources with these names already exist, inspect and reuse the intended configuration instead of replacing access policies.

```sh
PROJECT_ID="your-project-id"
PROJECT_NUMBER="$(gcloud projects describe "$PROJECT_ID" --format='value(projectNumber)')"
SERVICE_ACCOUNT="webstore-publisher@${PROJECT_ID}.iam.gserviceaccount.com"
POOL="wppconnect-github"
PROVIDER="extension-main"

gcloud services enable chromewebstore.googleapis.com iam.googleapis.com iamcredentials.googleapis.com sts.googleapis.com --project="$PROJECT_ID"
gcloud iam service-accounts create webstore-publisher --display-name="WPPConnect extension publisher" --project="$PROJECT_ID"
gcloud iam workload-identity-pools create "$POOL" --location=global --display-name="WPPConnect GitHub" --project="$PROJECT_ID"
gcloud iam workload-identity-pools providers create-oidc "$PROVIDER" \
  --location=global --workload-identity-pool="$POOL" --project="$PROJECT_ID" \
  --issuer-uri="https://token.actions.githubusercontent.com" \
  --attribute-mapping="google.subject=assertion.sub,attribute.repository_id=assertion.repository_id,attribute.repository_owner_id=assertion.repository_owner_id,attribute.ref=assertion.ref" \
  --attribute-condition="assertion.repository_id == '795275064' && assertion.repository_owner_id == '77944999' && assertion.ref == 'refs/heads/main'"
gcloud iam service-accounts add-iam-policy-binding "$SERVICE_ACCOUNT" \
  --project="$PROJECT_ID" --role=roles/iam.workloadIdentityUser \
  --member="principalSet://iam.googleapis.com/projects/${PROJECT_NUMBER}/locations/global/workloadIdentityPools/${POOL}/attribute.repository_id/795275064"
```

In the [Chrome Web Store Developer Dashboard](https://chrome.google.com/webstore/devconsole), link this service account email under **Account**. Google currently allows one linked service account per publisher; inspect any existing link before changing it. Find the publisher ID under **Publisher > Settings**.

## GitHub configuration and activation

Set these **repository Actions variables**, not secrets:

| Variable | Value |
| --- | --- |
| `CWS_PUBLISHER_ID` | Publisher ID from the Developer Dashboard |
| `CWS_WIF_PROVIDER` | `projects/PROJECT_NUMBER/locations/global/workloadIdentityPools/wppconnect-github/providers/extension-main` |
| `CWS_SERVICE_ACCOUNT` | `webstore-publisher@PROJECT_ID.iam.gserviceaccount.com` |
| `CWS_PUBLISH_ENABLED` | `true` after Google setup and account linkage are complete |

The workflow uses the `chrome-web-store` GitHub environment. Leave required reviewers unset for fully automatic submission. Both the workflow and the Google identity provider restrict execution to the official repository's `main` branch.

After activation, every subsequent release generated by `publish.yml` is submitted automatically. The store job calls the reusable workflow directly: GitHub release events created with `GITHUB_TOKEN` do not start a separate release-triggered workflow.

## Retry or publish an existing release

Open **Actions > Publish Chrome Web Store release > Run workflow**, choose `main`, and enter the stable release tag, for example `v1.0.96`. This submits the existing ZIP without creating a new release or incrementing its version.

The job treats a version already published or already pending review as complete. It rejects downgrades, preserves other pending reviews and staged revisions, and does not cancel submissions or change visibility. When another version is pending review, retry the latest intended release after that review completes. A rejected or cancelled revision with the same version requires inspection in the Developer Dashboard.

The Actions summary distinguishes `PENDING_REVIEW` from `PUBLISHED` and `PUBLISHED_TO_TESTERS`. A successful submission is not a claim that Google has approved the revision. If a publish response is lost, the job fails without blindly repeating the mutation; rerun after inspecting the store status.

To stop future submissions, set `CWS_PUBLISH_ENABLED` to `false`. This does not cancel a revision already under Google review.
